**更新日期：2026-11-08。**

引擎族已经锁定。目标平台和云存档是产品目标。微信小游戏怎么导出，仍是阻塞中的开放决策，本文不把它写成已解决。

## 已锁定

| 项 | 决定 | 来源 |
| --- | --- | --- |
| 引擎族 | **Unity 6 LTS + 2D / URP 2D Renderer + C#** | 工程负责人确认，2026-11-08 |
| MVP 进度 | **登录 + 云存档**。进度以账号上的云存档为准，本地文件只做缓存 | 产品经理提出的产品目标；微信上的登录方式随下面的导出方案一起复核 |

引擎族在导出方案写成 C 之前保持这条锁定。方案 C 会改掉它。现在没有选定 C。

在此锁定下的组成：

- 渲染：URP，使用其 2D Renderer。M1 不必开 2D 光照。
- 语言：C#。
- 内容：源数据放仓库 `content/`。运行时目标是 Addressables。M1 允许先直接读 JSON TextAsset。
- 输入：新工程使用 Input System 处理触控。
- 商业化：Services 层预留广告与 Unity IAP。垂直切片不接 SDK。
- 进度：MVP 走 Auth 与 CloudSave。见 [ARCHITECTURE.md](ARCHITECTURE.md)。

Godot 4 不在下面的导出方案里，本项目不并行 Godot 工程。

## 目标平台

产品目标（产品经理提出，微信路径仍在复核）：

**iOS + Android + 微信小游戏。**

这是要到达的平台，不是已经打通的导出能力。国内安卓多渠道会影响以后的广告和 IAP SDK，不改变引擎族，也不解决微信导出。

## 阻塞项：微信导出（OPEN）

标准 Unity **没有**微信小游戏的原生导出。此项未解决。在 A–D 写成书面选择之前，不生成完整的 Unity、团结引擎或 Cocos 工程。

建议**先评估 A**。评估用来核实事实，评估结束前 A 不是已选方案。

| 方案 | 做法 | 和当前锁定的关系 |
| --- | --- | --- |
| A | 团结引擎（Tuanjie Engine，Unity 中国）覆盖 iOS、Android 与微信小游戏 | 仍在 Unity / C# 族内，争取一份客户端。优先评估 |
| B | 双客户端：Unity 做 iOS / Android，Cocos 或 Web 做微信 | 引擎族仍服务原生两端。微信是第二套实现，架构边界两边都要守 |
| C | 三端都改用 Cocos Creator | 会撤销「引擎族 = Unity」这条锁定 |
| D | 先用 Unity 上 iOS / Android，微信小游戏以后再做 | 三端仍是产品目标。微信导出靠后，不在第一段工程里假装已经覆盖 |

优先评估 A 时要核实、而不是假设已经成立的点：

- 团结引擎与 Unity 6 LTS 工程的对应版本。
- 同一工程能否打出 iOS、Android 和微信小游戏。
- 登录与云存档在这三条导出上能否共用 Auth / CloudSave 接口。

核实结论写回本文，再选定 A、B、C 或 D。选 C 时同时改写「已锁定」一节。

## 登录与云存档

MVP 要求账号登录，进度写在云存档上。本地 `persistentDataPath` 只作为缓存。

供应商、微信登录组件、以及两台设备同时写入时的冲突规则，由 M0/M1 的 spike 定，不在本文指定产品名。IAP 票据校验可以晚于这个 spike。

微信上的登录通道取决于 A–D，正在和导出方案一起复核。复核改的是通道，不是把 MVP 退回「只存本地」。

## 其他仍开放的问题

这些不推翻引擎族。微信导出未选定之前，它们也不启动完整工程。

1. 相生邻接是四向还是八向，加成作用在伤害还是攻击间隔？见 [ARCHITECTURE.md](ARCHITECTURE.md)。
2. 漏怪失败条件的规则 id 由策划表定义。工程只预留字段。
3. 英雄移动空间：沿路径、可建造区，或固定站位？M3 用桩。
4. 运行时直接读 JSON，还是导入为 ScriptableObject 再打 Addressables？源 JSON 入库评审，M1 可直读。

数值（造价、生命、倍率、tick 赫兹、参考分辨率）另表填写。
