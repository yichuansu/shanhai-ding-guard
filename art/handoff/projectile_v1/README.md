## 5. 飞行速度、时序与拖尾

> **2026-11-11 定档（用户经制作人确认）**：真弹道，伤害在**命中 tick** 结算；飞剑速度 **0.0467 高度单位/tick**（稍慢档）。中距约 0.3 s，满射程约 0.6 s。塔特效改用 Alpha 版 `tower_jin_fx.png`。下文 5.2、5.3 已按此档更新。

### 5.1 工程里有没有弹道规则？——**没有**

在仓库里查过 PR #9 的改动、`docs/ARCHITECTURE.md`、`Assets/Game/**/*.cs`、`content/**/*.json`，**没有任何 projectile / 弹道 / 飞行速度 / 拖尾的规则或配置**。现在的规则是：

| 事实 | 出处 |
| --- | --- |
| 伤害在攻击 tick **当场结算**（即时命中，没有飞行时间）：`target.Hp -= damage` | `Assets/Game/Gameplay/CombatSimulation/CombatSimulation.cs` 第 521 行 |
| 逻辑 tick 10 Hz，`TickSeconds` = 0.1 s | `docs/ARCHITECTURE.md`「逻辑 tick 锁定 10Hz」 |
| 金塔 `attackIntervalTicks` = 8（墙钟 0.8 s）、`range` = 0.28 高度单位、`damage` = 10 | `content/towers/tower_jin.json` |
| 表现层按 `attackIntervalTicks` 自己计时，在塔位置播 `tower_jin_fx`（12 fps 单次 ≈ 0.33 s），只读快照、不写回模拟 | `BattleSpriteView.cs` `StepAttacks` / `SpawnFx`；ARCHITECTURE.md「换帧按模拟时间…」 |
| 攻击特效排序 3000，材质 `SpriteAdditive`（SrcAlpha One） | `BattleSpriteView.cs` `SortFx = 3000`；ARCHITECTURE.md 单位图表 |
| 当康速度 0.006 高度单位/tick = 0.06 高度单位/s ≈ 65 px/s@1080 | `content/enemies/enemy_dangkang.json`、ARCHITECTURE.md `combat.speed` |

上表是本包制作时仓库的现状（即时命中）。现在弹道规则已经由用户定了（见本节开头），按下面 5.2 接入。

| 项 | 值 |
| --- | --- |
| 发射点 | 飞剑子物体，本地 **(−0.183, 0)**（剑首后约 22 px；穗画在拖尾上面，不会被盖住） |
| Time | **0.25 s**（**随速度调整**：504 px/s 下约 126 px 长，和原 0.14 s@900 px/s 的视觉长度相同；可调 0.20–0.30。如果仍用 0.14 s，拖尾只有约 71 px，比剑本身还短，会显得很秃） |

| Min Vertex Distance | 0.05 world |
| Texture Mode | Stretch（左 = 头 u=0，右 = 尾） |
| Alignment | View |
| 材质 | URP `Particles/Unlit`，Transparent，Blending **Alpha**（或 Premultiply） |
| ⚠ 不要用 Additive | 冀州01 草地是亮黄绿 `#9DB22A`，任何颜色叠加上去都会偏向柠檬黄荧光（上次“偏柠檬”的主要原因之一）。贴图没有暗像素，技术上能用 Additive，但亮背景关卡请用 Alpha。 |

残影 `proj_jin_trail_afterimage` 可以代替 Trail（低配机），也可以和 Trail 叠用（GIF 第二剑就是叠用）。

- **残影间隔不用改**：它是挂在剑上的一张固定贴图（141 px），不按速度采样，换速度后形状不变；141 px 约等于新速度下 0.28 s 的飞行距离，和 0.25 s 的拖尾长度相当，两者叠用不会错位。
- 如果改成运行时采样残影（不用这张贴图），建议每 **0.05 s** 采一个（新速度下间隔约 25 px），保留 3 个。
- **剑身闪光** 0.33 s 一轮：满射程飞行 0.6 s 内会循环将近 2 次，可循环播；想要更干净，就只在出手时播一遍。
- 预览 GIF 和战斗合成图是按旧值 900 px/s、拖尾 0.14 s 合成的，只看造型和颜色即可；速度以本节为准。

## 6. 塔身重新配色（tower_jin_body）与 pivot 实测

- **用的就是 PR #9 的那张图**：仓库 `Assets/Game/Resources/BattleArt/tower_jin_body.png`（合并提交 `aeb2090`，main 上未再改），**192×192、PPU 160、pivot (0.5, 0.227)**。它和我们 v2 的 `master_2x/tower_jin_body@2x.png` 逐像素相同；我们 v2 的 96×96 只是它的 1× 缩小版，**工程里用的是 192 这张**。本包的 `master_2x/tower_jin_body@2x.png` 是它的直接替换图；`tower_jin_body.png`（96×96）由 @2x 缩小得到。
- **只改颜色**：金色像素（Lab 色度 > 约 40、色相 62°–122°）按亮度映射到锁定色板的两条色阶——剑扇里的亮部（剑刃）映射到暖银 `#AD8C51 → #F6F1E7 → #FEF5E9`，其余（剑格、塔身、宝顶）映射到金铜 `#2C1F18 → #51402F → #6A4D35 → #CB992C → #D8B68A → #F4D18B → #FEF5E9`。石座（灰米色）基本不动（平均 ΔE 0.13），原图边缘的淡粉色残留顺手改成奶白。
- **alpha 通道逐像素相同**（md5 `404717e1…` 前后一致），尺寸、剪影、底座椭圆位置都没有变化；`#211611` 类深色描边像素 4988 个，变化 > ΔE 2 的为 **0**。
- **pivot 实测**（对外轮廓 y ≥ 118 的底座段做椭圆拟合，α≥128）：

| 图 | 椭圆中心（px，左上原点） | 距底边 | 归一化 y | 半径 |

| PR #9 原图 192×192 | (95.62, 148.05) | 43.95 px | 0.2289 | 60.3×39.2 |

  前后**完全一致**，pivot (0.5, 0.227) 依旧落在底座椭圆中心。我们的拟合与 PR #9 写的 (96.0, 43.6) 相差 0.35 px（192 画布）= 0.002 world ≈ 0.3 px@1080，差异来自取点范围（取 y≥110 / 130 时分别得 44.7 / 42.9 px），在拟合误差内。

- **塔特效 `tower_jin_fx`**：同样来自 PR #9（4×192×192，PPU 160，pivot 中心）。剑身按塔身同一套色阶重新配色；原来按黑底提取、给 SrcAlpha One 叠加用的暗色辉光：

## 8. 已知弱点
